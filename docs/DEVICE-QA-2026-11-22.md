# On-device QA of core 0.13.0 (2026-11-22)

Run on the owner's Move with `tools/device_qa` (see its README): the installed host (md5 70b7f607..., core f91f2ea)
on a copy of the RemoteFM1 folder, the test hook on, output silent. About 18 minutes, 16 runs, ~330 screens. The
owner's own folder was not opened; afterwards the host was launched again the normal way.

## Result

- **0.13.0's tests:** 28 of 30 behave as written on the hardware, 1 partly (the Track tap's flash is on the step
  lights), 1 not checkable (the lights while Back is held).
- **0.12.0's tests:** 30 of 41 behave as written, 4 partly, 7 not checked (lights, sound, or not tried).
- The line on each card of the review page (its `rv8_qa.js`) says which.
- **Health:** no error in the host's log; engine blocks 0.3 to 0.7 ms on average of a 2.9 ms budget with three
  firmwares; the engine's `late` stayed 0. Five late audio transfers in all, each at the start or right after a
  project's firmwares loaded.

## Found

1. **Fixed in the core (51dfa1f, not in the installed build):** leaving session view with Menu names the view
   "Sequencer", which at that size is wider than the screen and showed as "equence". It is drawn at 2x now.
2. **A test on the review page was wrong (t13_s2).** The active state saves itself, so "save, change the sound,
   save to a second pad" leaves both pads with the changed sound. The test now saves both first, then changes.
3. **A test on the review page was wrong (t13_p2).** A project's pad opens it at the press, so the held screen
   always shows the firmwares now loaded; three dotted lines are seen only on a new project.
4. **To decide: an older project is converted when you leave it,** even with no edit. Opening project 10 (saved
   by 0.12.0) and going to another one wrote it as version 9 with copies of the three firmwares that happened to
   be loaded. The help says "at its next save".
5. **To decide: which state is "active" after a project loads.** Project 5 had state 1 active. Its duplicate
   (project 6) also had state 1 active; a change there went into state 1. Back in project 5 the sound was right
   (its own copy), but state 5, whose bytes equal that copy, was shown as active.
6. **To decide: a held Track + a held step selects that track too.** Flipping track 6's routing for firmware 1
   left track 6 selected for it (the press selects at once).
7. **Late audio transfers at a project load:** one or two each time, during the loading screen.
8. **Small:** the bar's note-length popup shows 1.25 steps as "+1.2".
9. **Seen, not a fault:** coming back to a track from another Track button shows the loop's first bar, not the
   bar that was on screen.

## Not checkable from here

Step, button, Track and knob lights (t13_b5, t13_t2's flash, t_sv6, t_co1, t_fb2, the lit knobs of t13_k1 and
t_la4, t_t41's icons); the sound by ear; t_lm3's wave over the pads; t_oc1's lag while the sweep runs; t_la3 (the
three Launch settings by ear); t_fb1.
